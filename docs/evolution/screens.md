# Экраны DEV/OS

Статус: дизайн следующей версии. Все цифры в макетах демонстрационные.
Термины и архитектура описаны в [architecture.md](architecture.md).

## Общая оболочка

Сверху: workspace, имя экрана, источник каждой активной панели и владелец ввода.
Снизу: доступные действия в текущем контексте. Любой виджет можно развернуть
на всё окно и вернуть обратно с сохранением состояния.

Предлагаемые новые клавиши действуют **только при фокусе DEV/OS**:

| Клавиша | Действие |
| --- | --- |
| `1`…`7` | Выбрать экран |
| `P` | Палитра команд: поиск экрана, визуала, источника, пресета, действия |
| `?` | Справка именно для текущего экрана |
| `o` / `O` | Следующая / предыдущая панель; регистр различается |
| `Z` | Развернуть выбранную панель / вернуть раскладку |
| `G` | Существующий выбор графики и её параметров |
| `Tab` | Существующий выбор сцены кода и общих опций |
| `F2`, `Ctrl+]` | Существующий переход между вводом в терминале и DEV/OS |
| `F3` | Существующее переключение SOURCE / терминал в рабочей панели |

`Esc` сначала закрывает overlay или развёрнутую панель. Выход через `Q`
сохраняется. В терминале цифры, `Tab`, `P`, `G`, `Esc` и остальные обычные
клавиши получает дочернее приложение. Владелец ввода виден постоянно:
`INPUT: DEVOS`, `INPUT: CODEX`, `INPUT: CLAUDE`.

У Arena появляется отдельная команда `Stop mission` и резервное сочетание
`Ctrl+]`, затем `!`. `!` при dashboard-фокусе останавливает запуск новых ходов
и запрашивает отмену активных managed-ходов. В терминале `!` остаётся обычным
символом. В меню всегда есть та же команда; знать сочетание необязательно.

### Размеры

- **160×44 и больше:** две терминальные панели с общей лентой; третья колонка
  появляется только от 200 символов, если помещается её минимальная ширина.
- **120×36:** основная рабочая панель и один вспомогательный прибор; Arena
  может показывать две компактные текстовые карточки или один терминал с вкладками.
- **80×24:** одна основная панель, вкладки остальных и строка важных событий.
- **48×16:** управление, одна панель и компактный статус; декоративные части скрыты.
- Ниже минимального размера видны сообщение и способ вернуть dashboard-фокус.

При уменьшении окна процесс не перезапускается. Дочерний PTY получает размер
своей действительной области; скрытая панель сохраняет последний полезный размер.
Пресет задаёт приоритет панелей, а не жёсткие координаты пикселей.

## 1. Cockpit / Bridge

Экран для реальной работы. По умолчанию — следующий шаг от нынешней композиции.

```text
 DEV/OS / ekza-sdk   COCKPIT   INPUT: CODEX   LIVE 2 | DEMO 1
+----------------------------------------+---------------------+
| CODEX / workspace / branch              | PLASMA REACTOR      |
| > implement avatar validation          |          (@)        |
|                                        | tests -> shield     |
| [real terminal]                        | git -> sparks       |
|                                        | source: DEMO        |
+----------------------------------------+---------------------+
| last test: 14/15 FAIL  | git: 3 files  | agent: needs input    |
+--------------------------------------------------------------+
| 12:04 test failed -> [inspect]  12:05 patch ready -> [open]     |
+--------------------------------------------------------------+
```

Основная панель принимает терминал, исходник или diff. Справа один большой
визуал и до трёх коротких фактов. Синусоида остаётся выбираемым нижним виджетом.
Отдельный индикатор сообщает, что исходники настоящие, а сборка демонстрационная;
одна общая метка `LIVE` не должна делать всю композицию «настоящей».

Сценарий: открыть сохранённый `night-shift`, войти в Codex, свернуть графику
на время чтения diff, затем вернуть её. Событие ошибки подсвечивает карточку,
но не открывает другое окно и не перехватывает клавиатуру.

Приёмка: нынешний запуск воспроизводится этим экраном; сохранение/разворачивание
панелей не сбрасывает CLI-процесс и печать демо-кода.

## 2. Visual Lab / Patchbay

Лаборатория графики: быстрый выбор готовых связей, затем настройка их диапазонов.

```text
 VISUAL LAB / preset: night-shift / unsaved changes
+---------------------+-----------------------+------------------+
| SOURCE              | BINDING               | PREVIEW          |
| demo.visitors       | -> particle.count     |      .  *        |
| git.changed_files   | -> ring.energy        |    * (@) .       |
| body.bpm            | -> core.pulse         |      .   *       |
| test.run.completed  | -> shield.close       |                  |
+---------------------+-----------------------+------------------+
| selected: visitors -> count  | log scale | clamp 0..200        |
| missing: fade + STALE        | smooth .8s | [save] [reset]      |
+--------------------------------------------------------------+
```

В первой версии это список готовых связей с формами, не свободный редактор
узлов. Человек выбирает визуал, сигнал и нормализацию. Справа немедленный
DEMO-preview; под ним объяснение: «точки показывают интенсивность, точный
показатель рядом». Если источник отсутствует, числовая карточка показывает `--`.

Можно сохранить капсулу пресета с темой, visual seed, раскладкой и bindings.
В экспорт не входят ключи, команды запуска, локальные абсолютные пути и
выбранные устройства, если пользователь отдельно их не включил.

Приёмка: связать `demo.online` с плотностью частиц без редактирования Python;
переключить в LIVE без источника и увидеть честный `UNAVAILABLE`.

## 3. Agent Arena / Duet

Две полосы работы и отдельная полоса общения. Подробности — в
[agent-arena.md](agent-arena.md).

```text
 ARENA / avatar-parser / PARALLEL TASKS / 2 ACTIVE / HANDOFF 2/6
+-------------------------------+-------------------------------+
| CODEX / implementer            | CLAUDE / test designer        |
| task: implement parser         | task: adversarial cases       |
| turn: running  | owner: DEVOS  | turn: running | owner: DEVOS  |
| [terminal OR managed events]   | [terminal OR managed events]  |
+-------------------------------+-------------------------------+
| TRANSFER  #12  CODEX -> CLAUDE / review_request / READY        |
| artifact: patch@abc  tests: report@18  question: check bounds  |
| [inspect] [edit and send] [pause mission] [stop mission]       |
+--------------------------------------------------------------+
```

Три уровня: `Watch` — человек управляет двумя терминалами; `Relay` — передаёт
выбранные завершённые сообщения; `Mission` — управляет конечным сценарием.
В managed-представлении показываются сообщения, действия инструментов и
артефакты, которые предоставляет адаптер. Не дорисовываются скрытые «мысли».

Сверху всегда видны режим, текущая фаза, активные задания, использованные
handoff и время. Расход показывается как reported estimate, если доступен;
отсутствующие данные о стоимости обозначаются `unknown`, а не нулём.

Во время параллельной работы у двух агентов разные задачи и рабочие копии.
Результаты встречаются на явном handoff. В режиме ревью передаётся определённый
патч/commit, а не изменяющаяся папка второго агента.

Приёмка: ввод в Codex не оказывается в Claude; `Stop mission` доступен при
любом выбранном экране через command palette и резервную последовательность.

## 4. Site Observatory / Audience Orbit

Посещения сайта как карта движения. Пространственная карта — схема страниц,
а не вымышленная география посетителей.

```text
 SITE / my-site / LIVE / received 0.8s ago / quality: OK
+---------------------------------------+----------------------+
|      [blog] ---- [project]             | ACTIVE SESSIONS 28   |
|         . \       / .                 | window: last 60s     |
|  arrival -> [home] -> [ekza]           | /ekza         12     |
|    *       .      *                   | /devos         9     |
|                                       | /about         7     |
+---------------------------------------+----------------------+
| 1 dot ~= 5 sessions / aggregate mode  | views/min: 84         |
+--------------------------------------------------------------+
```

Если источник отдаёт агрегаты, показываем стаи и агрегаты. Персональные
траектории появляются только при наличии соответствующих событий с допустимым
временным session ID. Узлы стабильны между обновлениями: данные не должны
перетряхивать карту каждые две секунды.

Выбор узла фильтрует ленту и подробности страницы. `Traffic surge` запускает
ограниченный метеорный след. Реальные счётчики сохраняют смысл и временное окно.
Для GA4 карточка называется `ACTIVE USERS / 30m`, а не текущий онлайн.

Приёмка: отключить поставщика, увидеть возраст последнего образца и `STALE`,
затем `OFFLINE`; вымышленные посетители не подмешиваются в LIVE.

## 5. Body Signal / Biolink

Личный ритм как источник света и движения. Конкретное устройство подключается
позже через адаптер; экран полноценно работает с подписанным DEMO.

```text
 BODY SIGNAL / chest-strap / LIVE / received 0.3s / contact: OK
+---------------------------------------------+----------------+
|             .- expanding shell -.           | 72 BPM         |
|         <-- pulse-derived wave -->          | RR: available  |
|                (@)                          | age: 0.3s      |
+---------------------------------------------+----------------+
| RR intervals, ms:   . .  . . . .      | binding: core.pulse  |
+--------------------------------------------------------------+
```

Три представления: измеренный BPM; точки измеренных RR-интервалов, если
они есть; художественная пульсация. Кривая, синтезированная из BPM,
подписывается `BPM-DRIVEN VISUAL`, не ЭКГ. Уведомление устройства не обязательно
содержит аппаратный timestamp каждого удара; качество времени хранится отдельно.

При потере связи число тускнеет с возрастом образца, затем исчезает. Анимация
переходит в нейтральный idle с явным `NO SIGNAL`. Личные значения не включены
в общий экспорт/Stream View по умолчанию. Экран не вычисляет диагнозы или
«уровень стресса» из красивой картинки.

Приёмка: BPM-only источник не создаёт мнимые measured-beat события; отключённый
датчик не продолжает отображаться как LIVE.

## 6. Ekza Atlas / RepoVerse

Два представления одной рабочей области: `Assets` и `Repository`.

```text
 EKZA ATLAS / ASSETS / SNAPSHOT / consumer: SPACE
+-------------------------------------------+------------------+
| identity *----* revision                   | avatar: example  |
|              /     \                      | revision: r004   |
|      rendition *---* approval             | profile: vrm...  |
|                   \                       | bytes/hash: ...  |
|                    * consumer             | origin: fixture  |
+-------------------------------------------+------------------+
| [Assets] [Repository] | selected edge: verifies exact bytes   |
+--------------------------------------------------------------+
```

В Assets выбирается аватар/ассет и видны связи identity, immutable revision,
rendition, approval и consumer. Цвет не выдаёт потребительскую approval за
универсальную истинность ассета. Источник графа — явный fixture, локальный
manifest или будущий catalog adapter, а не произвольная генерация из названий.

Repository начинает с настоящего Git-дерева и изменённых файлов. Звезда — файл,
группа — каталог, яркость — факт изменения. Рёбра dependencies рисуются только
при наличии анализатора; иначе рёбра означают структуру каталогов. Выбранная
звезда открывает diff/исходник, а действие «передать агенту» готовит контекст.
Git-проверки здесь только читают состояние, не выполняют merge/deploy.

Приёмка: fixture протокола, локальный Git и реальный consumer не смешиваются
под одной подписью; у каждого выделенного узла можно узнать происхождение.

## 7. Replay Studio / Flight Recorder

Лента конкретных событий, а не запись каждого графического кадра.

```text
 REPLAY / evening-session / x4 / NO LIVE ACTIONS
+--------------------------------------------------------------+
|              reproduced cockpit / arena / atlas               |
+--------------------------------------------------------------+
| --o------o---[X]--------o-----------------|---------------->   |
|   build  handoff fail   fixed             playhead             |
| [play] [seek] [next failure] [bookmark] [export capsule]        |
+--------------------------------------------------------------+
```

Закладки создаются вручную или на событиях: ошибка теста, готовый патч,
всплеск посещений. Seek восстанавливает ближайший checkpoint и события до
нужного времени. Настройка скорости меняет playhead, а не значения показателей.

По умолчанию запись содержит нормализованные события, seed и параметры сцены.
Полные промпты и терминальный текст — отдельный opt-in. Если их не записывали,
вместо терминала виден placeholder «terminal content not recorded».
В повторе нажатие на событие команды открывает его детали, а не исполняет его.

Приёмка: один файл без сети и установленных CLI воспроизводит те же значения
и последовательность эффектов. Зафиксированная версия renderer/seed нужна для
побитового сравнения; разные терминальные шрифты не обещают одинаковые пиксели.
